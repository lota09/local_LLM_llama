# 남은 측정 — 메모

SSD 페이징 측정에서 아직 안 한 것. 보고서
[토큰 하나의 원가](https://claude.ai/code/artifact/aeaa4910-bef2-4267-8acd-37b3cd158c6d)
의 §9 한계와 짝이다. 하네스는 전부 `scratchpad` 에 있던 것과 같은 모양이면 된다:
짧은 고정 프롬프트 + 매 런 다른 seed + `ignore_eos` + `/proc/<pid>/{io,stat}` 계측.

기준 모델: `토큰시간 = 커널항 + 16 × 미스율 × 폴트지연`
(커널항 18.2~21.0 ms · 폴트지연 NVMe 209 µs / HDD 7,280 µs)

## B. 저미스 구간 (0~35%) — 우선순위 1

**재는 것.** 워밍을 길게 돌리며 미스율이 어디까지 내려가고 몇 토큰 만에 평평해지는지.

**왜.** 지금 모델은 미스 **35~100%** 에서만 검증됐다. 오래 띄워둔 서버의 실제 운용 구간은
그 아래다. 그리고 이게 **RAM 증설 결정**을 답한다:

| 현재 미스율 | 절반으로 낮추면 | 이득 (NVMe) | 이득 (HDD) |
|---:|---:|---:|---:|
| 80% → 40% | | 6.1% | 69.5% |
| 40% → 20% | | 3.1% | 53.2% |
| 20% → 10% | | 1.6% | 36.2% |

30 → 64 GiB 증설이 NVMe 에서 **1.6~6.1%** 밖에 못 번다. 어느 줄인지 알아야 결정이 선다.

**이미 나온 단서.** 접근이 균등하다면 미스율 하한은 `1 − 21 GiB / 35.8 GiB = 41.3%` 인데
**측정 최저가 34.8%** 로 그 아래다. n-gram 접근이 편향돼 있다는 증거다.
B 는 그 편향이 어디까지 데려가는지를 본다.

> 페이지 캐시가 차오르는 것과 메모리 압박은 무관하다 — clean·파일 백드라 커널이
> 필요할 때 공짜로 버린다. 남는 RAM 을 채우고 멈출 뿐이다.

## A. 토큰 시간의 분포 (p99)

**재는 것.** 스트리밍으로 토큰별 도착 시각을 받아 미스율별 **분포**를 그린다.

**왜 두 가지.**

1. **체감.** 대화형에서 느껴지는 건 평균이 아니다. 모델 예측:
   NVMe 미스 50% → 평균 22.30 / p99 23.35 ms (비 1.05).
   HDD 미스 50% → 평균 78.73 / p99 115.13 ms (비 1.46).
   NVMe 는 평균만 싼 게 아니라 **분산도 작을 것**으로 예측된다.
2. **구조.** 위 예측은 16개 행의 미스가 **독립**이라고 가정한다(이항분포). 실제로는
   2-gram 8행 + 3-gram 8행 **두 그룹**이고, 같은 그룹이 테이블에서 인접하면 미스가
   **뭉친다**. 측정하면 갈린다 — 뭉치면 **그룹 단위 프리페치**가 통한다는 뜻이고
   llama.cpp 에 붙일 수 있는 최적화가 된다.

HDD 는 회전 지연만으로 0~8.3 ms 가 요동치므로 **실제 지터는 위 예측보다 나쁠 것**이다
(그 분산원은 모델에 안 들어 있다).

## C. 동시성 × 미스율

**재는 것.** 1/2/4 동시 스트림에서 **폴트당 비용**을, 폴트 수를 맞춰 비교.

**두 효과를 분리해야 한다.**

| | 효과 | 어떻게 드러나나 |
|:---|:---|:---|
| ① | 캐시 공유 — 다른 요청이 올린 페이지 재사용 | **폴트 수**가 준다 |
| ② | **큐 깊이** — 게더가 동시에 나가 폴트당이 싸진다 | **µs/폴트**가 준다 |

노리는 것은 ②다. 실측된 큐 깊이는 디코드 **1.0**, 프리필 **1.5** 뿐인데
이 장치는 QD8 에서 26,121 op/s(38 µs), QD32 에서 43,847 op/s(23 µs)를 낸다.

- ②가 일어나면 → 바쁜 서버가 토큰당 페이징 비용을 **덜** 낸다. **1인 사용이 최악**이 되고
  용량 산정이 바뀐다.
- 안 일어나면 → 페이징 비용은 부하와 무관한 고정 세금이고, llama.cpp 최적화 공백이 하나 더.
